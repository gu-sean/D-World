# D-World

목표를 미션으로, 미션을 습관으로 만드는 목표 관리 앱. 파트별 상세는 각 폴더의 README를 본다.

```
backend/     NestJS API (김상구)
db/          PostgreSQL 마이그레이션 (김상구)
ai/          FastAPI 비전·LLM 서버 (김재현)
mobile/      React Native 앱 (이연수·최정훈)
admin-web/   관리자 웹 (프로이드·네토)
```

## 현재 되는 기능

### 모바일 앱 (React Native, Android)
- **가입·로그인:** 휴대폰 번호 + 비밀번호(번호 → 비밀번호 → 닉네임), 약관 동의·재동의, 비밀번호 재설정
- **홈:** 주간 달력, 오늘 진행률, 오늘의 미션, 챌린지 배너, 상황 추천 입구
- **목표:** 목표 만들기("AI 계획 받기" 또는 "직접 계획 짜기"), 단계·세부 미션 관리, AI 재조정 제안, 빈 주 채우기, 난이도 추천(나이·키·몸무게 기반)
- **미션:** 미션 틀 고르기·직접 만들기·수정·취소, 예상 난이도·포인트 미리 보기, 다음 미션 추천
- **운동 인증:** 영상 촬영(최대 10분, 압축)·업로드, AI 자동 판정(푸시업·스쿼트·런지·플랭크·버피), 재촬영 안내, 러닝 거리·걸음 수 기록
- **보상:** 포인트(월 한도), 연속 일수(스트릭), 업적·배지, 포인트 상점
- **펫:** 알 고르기 → 부화 → 진화(알→아기→성체), 도감 21종, 움직이는 GIF, 대표 펫 설정
- **챌린지:** 공개 챌린지 목록·참여·포기, 랭킹, 결과
- **리포트:** 주간·월간 달성률, 월간 달력, AI 리포트
- **추천:** 기상청 실제 날씨·상황 기반 미션 추천, 깜짝 미션, 추천 피드백
- **마이:** 프로필 수정, 알림함, 공지사항, 문의·신고, 설정(알림·진동), 회원 탈퇴
- **사용 편의:** 불러오는 동안 스켈레톤, 오류 시 안내 화면과 다시 시도, 키보드가 입력칸을 가리지 않게 자동 이동, 화면 읽기(접근성) 이름, 보상 순간의 진동

### 관리자 웹 (React + Vite)
- 로그인, 대시보드, 회원 관리, 문의·신고 처리, 인증 검수(처리 대기), 미션 틀 관리, 챌린지 개설·관리, 업적·펫 종류·상점 관리와 이미지 업로드, 공지·약관·정책 등 운영 콘텐츠, 감사 로그

### 백엔드·AI·DB
- **백엔드:** 앱 API(`/api/v1`), 관리자 API(`/admin/v1`), AI 콜백용 내부 API(`/internal/v1`), JWT 인증·요청 횟수 제한·중복 요청 방지, 정기 작업 19종(서버가 여러 대여도 한 곳만 실행)
- **AI 서버:** MediaPipe 관절 추출 + 규칙 기반 운동 판정(자동 승인·반려·검토), 같은 영상 재제출·촬영 전 영상 차단, Gemini 기반 목표 계획·난이도 추천·리포트(키가 없거나 실패하면 규칙 기반 예비 계획)
- **DB:** PostgreSQL 17(Supabase 공유 DB), 표 94개 + 이력 표, 모든 표에 행 수준 보안(RLS), 원장·정책 버전은 수정·삭제 차단

## 아직 안 된 것

- **구독·결제:** 앱은 "준비 중" 안내만 보여 주고, 서버는 로그인한 사용자에게 항상 501(`COMMON_NOT_IMPLEMENTED`)을 돌려준다.
- **소셜 로그인(구글·네이버):**
  - 앱에 구글·네이버 로그인 SDK가 없고, 개발 모드(`SOCIAL_LOGIN_MODE=mock`)에서는 모의 토큰만 보낸다.
  - 서버의 `SOCIAL_DRIVER` 기본값이 `real`이라, 지금 설정에서는 소셜 로그인 버튼이 "소셜 로그인에 실패했어요"로 끝난다(구글·네이버 모두 확인). 서버를 `SOCIAL_DRIVER=mock`으로 바꾸면 모의로 동작한다.
  - 실제 연동에는 SDK 설치와 서버의 클라이언트 ID(`GOOGLE_CLIENT_IDS` 등) 설정이 필요하다. 앱은 애플 로그인은 호출하지 않는다.
- **Gemini:** `ai/.env`의 `GEMINI_API_KEY`가 비어 있다. 키가 없으면 AI 서버가 실제 LLM 대신 모의(mock)와 규칙 기반 예비 계획으로 동작한다(상태 점검에서 `llm: mock` 확인).
- **러닝 센서 인증·사진 증거의 AI 판정:** 서버 기본값이 꺼짐이다(`AI_SENSOR_ENABLED=false`, `AI_PHOTO_ENABLED=false`). 해당 인증은 관리자 검수로 처리된다.
- **운동 판정 정확도:** 실제 사람 영상으로 운동별 횟수·각도 기준을 충분히 검증하지 못했다(단위 테스트만 있다).
- **AI 재조정 수락 시 미션 중복(가능성):** 재조정 수락은 계획 수락과 같은 함수를 쓰고, 이 함수는 새 계획에 나온 날짜의 "시작 전 AI 미션"만 취소한다. 새 계획이 날짜를 옮기면 옛 날짜의 AI 미션이 남을 수 있다. 코드로는 확인했지만 실제로 재현하지는 못했다.

## 공유 DB(Supabase)로 바로 띄우기

```bash
cd backend && npm install && npm run demo:supabase
```


## 로컬 DB로 처음 띄우기

Docker Desktop을 켜 둔 상태에서:

```bash
# 1) DB 띄우고 표 만들기
cd backend
npm install
npm run db:reset                 # public 스키마를 지우고 마이그레이션 처음부터 적용
DEV_ADMIN_PASSWORD=비번 DEV_USER_PASSWORD=비번 npm run db:seed
#   → 분야·난이도·정책·약관·관리자 계정과 기본 업적(배지) 6개가 들어간다 (미션·펫·사용자 데이터는 비어 있음)

# 2) 서버 실행
npm run start:dev
```

## AI 서버 · 관리자 웹 · 모바일 실행

```bash
# AI 서버 (영상 판정·LLM). ai/.env를 ai/.env.example에서 복사해 만들고 GEMINI_API_KEY를 넣는다
cd ai && python -m venv .venv && .venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
#   백엔드 .env에 AI_SERVICE_URL=http://127.0.0.1:8001, INTERNAL_API_TOKEN(ai/.env와 같은 값)이 있어야 연결된다

# 관리자 웹
cd admin-web && npm install && npm run dev

# 모바일 (에뮬레이터·기기 먼저 연결)
cd mobile && npm install && cp .env.example .env && npm run android
```

## 운영 규칙 (관리자 웹)

- 챌린지는 관리자만 만들고 관리한다. 회원은 참여·포기만 한다 (회원 개설 API는 403).
- 인증 판정은 AI가 먼저 한다. 관리자는 **인증 검수 > 처리 대기**(이의 신청 + AI 판정 보류)에서만 판정하고, 모든 결과는 **인증 기록**(읽기 전용)에 남는다.
- 관리자 작업의 사유는 선택이다. 비우면 감사 로그에 "관리자 처리"로 남는다.
- 게시한 공지도 분류·제목·내용·이동 화면은 고칠 수 있다 (받는 회원·푸시는 그대로). 챌린지는 참가자가 생겨도 제목·설명을 고칠 수 있다 (`db/migrations/018`).
- 사용자 XP는 관리자 화면에서 정하지 않는다. 미션 보상표는 포인트와 같은 값, 연속 일수·업적·챌린지는 0으로 저장된다.
- 회원은 모든 목록에서 "닉네임 또는 회원 ID"로 찾는다 (회원 ID 전체 표시 + 복사 버튼).

## 목표·보상 규칙 (앱)

- 최종 목표에는 보상이 없다. 목표를 만들 때 난이도를 고르지 않는다 (API에서 생략하면 `normal`로 저장, 보상에 쓰이지 않음).
- 보상은 하루하루의 **세부 미션마다** 받는다. 미션 난이도는 사용자가 고르지 않고 미션 내용(운동 종류·목표 수치·소요 시간)으로 규칙이 정한다 (`backend/src/missions/difficulty-rules.js`). 그 난이도의 관리자 보상표 포인트(쉬움 10 · 보통 20 · 어려움 30)가 미션을 만들 때 고정된다. AI가 금액을 정하는 경로는 없다.
- 직접 만든 미션·AI 계획·빈 주 채우기 모두 같은 규칙을 쓴다. 앱은 미션 폼에서 `POST /missions/difficulty-preview`로 "예상 난이도 · 포인트"를 미리 보여 준다.
- 수치를 고쳐 난이도가 달라지면 수정이 막힌다 (409 `difficulty_changed`). 미션을 취소하고 새로 만들어야 한다.
- 목표를 만들 때 "AI 계획 받기"와 "직접 계획 짜기" 중 하나를 고른다. 목표 상세에서 세부 미션을 보고 추가·수정·취소한다.
- 세부 미션이 "주 N회"보다 적은 주는 `GET /goals/:id/gaps`로 찾고, 목표 상세가 "AI가 채워 주기 / 빈칸으로 두기"를 묻는다. 빈 주에는 미션이 없으니 보상도 없다.
- 펫 경험치는 미션마다 보상표 값이 쌓인다(하루 한 번만 주려면 DB 트리거를 바꿔야 해서 보류).

## 개발 환경 설정 (backend/.env)

개발 중에는 아래처럼 실제 키·서버 없이도 돌아가게 둔다. 실제 값은 운영·시연 때 바꾼다.

| 설정 | 개발 기본값 | 뜻 |
|---|---|---|
| `SMS_DRIVER` | `console` | 문자를 서버 로그에 출력 (앱 가입·재설정은 인증번호를 쓰지 않음, 번호 변경 `me/phone/codes`만 사용) |
| `SOCIAL_DRIVER` | `real`(기본) | 소셜 토큰을 실제로 검증. 앱이 모의 토큰을 보내는 개발 중에는 `mock`으로 바꿔야 로그인된다 |
| `WEATHER_DRIVER` | `kma` | 기상청 API허브의 실제 날씨(키는 `.env.supabase`에 있음). 키가 없으면 `mock`으로 두면 항상 맑음 20도 |
| `PUSH_DRIVER` | `console`(비어 있으면 같음) | 푸시를 서버 로그에만 남김 (`fcm`으로 바꾸면 실제 발송, 서비스 계정 필요) |
| `STORAGE_DRIVER` | `memory` | 인증 파일이 서버 메모리에만 남음 (`r2`로 바꾸면 Cloudflare R2) |
| `AI_SERVICE_URL` | AI 서버 주소 | 비우면 AI 서버 없이 규칙 기반 대체물로 동작 |
