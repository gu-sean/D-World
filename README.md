# D-World

목표 관리 앱. 파트별 상세는 각 폴더의 README를 본다.

```
backend/     NestJS API (김상구)
db/          PostgreSQL 마이그레이션 (김상구)
ai/          FastAPI 비전·LLM 서버 (김재현)
mobile/      React Native 앱 (이연수·최정훈)
admin-web/   관리자 웹 (프로이드·네토)
```

## 처음 띄우기

Docker Desktop을 켜 둔 상태에서:

```bash
# 1) DB 띄우고 표 만들기
cd backend
npm install
npm run db:reset                 # public 스키마를 지우고 마이그레이션 처음부터 적용
DEV_ADMIN_PASSWORD=비번 DEV_USER_PASSWORD=비번 npm run db:seed
#   → 분야·난이도·정책·약관·관리자 계정과 기본 업적(배지) 6개가 들어간다 (미션·펫·사용자 데이터는 비어 있음)

# 2) 서버 실행
npm run start:dev
```

미션 틀·펫 종류·상점 물건은 관리자 웹에서 직접 만든다. 기본 업적 6개(첫 목표 달성·미션 10개·미션 50개·운동 20회·7일 연속·첫 챌린지 완주)는 시드에 있고, 관리자 웹 업적 화면에서 고치거나 더 만든다.
앱 사용자는 앱에서 직접 가입한다 (휴대폰 인증번호 단계 없음: 번호 입력 → 비밀번호 설정 → 닉네임).
챌린지 탭에는 관리자 웹에서 만든 공개 챌린지만 보이고, 없으면 "다음 챌린지를 기대해 주세요."가 뜬다.

### 운영 규칙 (관리자 웹)

- 챌린지는 관리자만 만들고 관리한다. 회원은 참여·포기만 한다 (회원 개설 API는 403).
- 인증 판정은 AI가 먼저 한다. 관리자는 **인증 검수 > 처리 대기**(이의 신청 + AI 판정 보류)에서만 판정하고, 모든 결과는 **인증 기록**(읽기 전용)에 남는다.
- 관리자 작업의 사유는 선택이다. 비우면 감사 로그에 "관리자 처리"로 남는다.
- 게시한 공지도 분류·제목·내용·이동 화면은 고칠 수 있다 (받는 회원·푸시는 그대로). 챌린지는 참가자가 생겨도 제목·설명을 고칠 수 있다 (`db/migrations/015`).
- 사용자 XP는 관리자 화면에서 정하지 않는다. 미션 보상표는 포인트와 같은 값, 연속 일수·업적·챌린지는 0으로 저장된다.
- 회원은 모든 목록에서 "닉네임 또는 회원 ID"로 찾는다 (회원 ID 전체 표시 + 복사 버튼).

### 목표·보상 규칙 (앱)

- 최종 목표에는 보상이 없다. 목표를 만들 때 난이도를 고르지 않는다 (API에서 생략하면 `normal`로 저장, 보상에 쓰이지 않음).
- 보상은 하루하루의 **세부 미션마다** 받는다. 미션 난이도는 사용자가 고르지 않고 미션 내용(운동 종류·목표 수치·소요 시간)으로 규칙이 정한다 (`backend/src/missions/difficulty-rules.js`). 그 난이도의 관리자 보상표 포인트(쉬움 10 · 보통 20 · 어려움 30)가 미션을 만들 때 고정된다. AI가 금액을 정하는 경로는 없다.
- 직접 만든 미션·AI 계획·빈 주 채우기 모두 같은 규칙을 쓴다. 앱은 미션 폼에서 `POST /missions/difficulty-preview`로 "예상 난이도 · 포인트"를 미리 보여 준다.
- 수치를 고쳐 난이도가 달라지면 수정이 막힌다 (409 `difficulty_changed`). 미션을 취소하고 새로 만들어야 한다.
- 목표를 만들 때 "AI 계획 받기"와 "직접 계획 짜기" 중 하나를 고른다. 목표 상세에서 세부 미션을 보고 추가·수정·취소한다.
- 세부 미션이 "주 N회"보다 적은 주는 `GET /goals/:id/gaps`로 찾고, 목표 상세가 "AI가 채워 주기 / 빈칸으로 두기"를 묻는다. 채우기(`POST /goals/:id/gaps/fill`)는 AI 서버 연동 전까지 규칙 기반이다. 빈 주에는 미션이 없으니 보상도 없다.
- DB 스키마는 바꾸지 않았다. 펫 경험치는 지금처럼 미션마다 보상표 값이 쌓인다. 하루 한 번만 주려면 DB 트리거를 바꿔야 해서 보류했다.

```bash
# 관리자 웹
cd admin-web && npm install && npm run dev

# 모바일 (에뮬레이터·기기 먼저 연결)
cd mobile && npm install && cp .env.example .env && npm run android
```

## 지금 가짜로 돌아가는 것 (backend/.env)

실제 키·서버가 붙기 전까지 이렇게 둔다.

| 설정 | 값 | 뜻 |
|---|---|---|
| `SMS_DRIVER` | `console` | 문자를 서버 로그에 출력 (앱 가입·재설정은 인증번호를 쓰지 않음, 번호 변경 `me/phone/codes`만 사용) |
| `SOCIAL_DRIVER` | `mock` | 소셜 로그인 토큰을 검증 없이 신뢰 |
| `WEATHER_DRIVER` | `mock` | 항상 맑음 20도 |
| `PUSH_DRIVER` | `console` | 푸시 발송 안 함 |
| `STORAGE_DRIVER` | `memory` | 인증 파일이 서버 메모리에만 남음 |
| `AI_SERVICE_URL` | 빈칸 | AI 서버 미연결 — 계획은 규칙 기반 대체물 |
